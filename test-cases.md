# Чек-лист тест-дизайна: User Management REST API (Kaspersky SDET)

Данный документ содержит полный перечень позитивных, негативных, граничных и нефункциональных тест-кейсов для проверки сервиса управления пользователями `UserManagement.API` в соответствии с требованиями тестового задания (включая все дополнительные задания).

---

## 1. POST /api/users — Создание пользователя

### Позитивные проверки (Positive Cases)
- [ ] **TC-POST-01**: Успешное создание пользователя с валидными данными (`CountryIsoCode: "RU"`, `Locale: "ru-RU"`).
  - *Ожидаемый результат*: HTTP 201 Created; заголовок `Location` указывает на `/api/users/{userId}`; тело ответа содержит валидный JSON с сгенерированным `userId` (!= `Guid.Empty`), `dateCreated` (текущее время UTC), `dateModified: null`, `countryIsoCode: "RU"`, `locale: "ru-RU"`.
- [ ] **TC-POST-02**: Автоматическое приведение `CountryIsoCode` к верхнему регистру (UPPERCASE) при сохранении (передано `"ru"`, сохранено `"RU"`).
  - *Ожидаемый результат*: HTTP 201 Created; в ответе и при последующем чтении `countryIsoCode` равен `"RU"`.
- [ ] **TC-POST-03**: Создание пользователя с различными международными валидными локалями (`en-US`, `de-DE`, `fr-FR`, `zh-CN`, `ja-JP`).
  - *Ожидаемый результат*: HTTP 201 Created; данные сохранены без искажений.
- [ ] **TC-POST-04**: Проверка целостности схемы ответа и типов полей.
  - *Ожидаемый результат*: `userId` имеет тип Guid, `dateCreated` является валидной датой (не `default(DateTime)`), `dateModified` равен `null`.

### Негативные проверки валидации (Validation & Negative Cases)
- [ ] **TC-POST-05**: Валидация `CountryIsoCode` — пустая строка `""`.
  - *Ожидаемый результат*: HTTP 400 Bad Request с описанием ошибки валидации поля `CountryIsoCode`.
- [ ] **TC-POST-06**: Валидация `CountryIsoCode` — строка из пробелов `"   "`.
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-07**: Валидация `CountryIsoCode` — значение `null`.
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-08**: Валидация `CountryIsoCode` — длина меньше 2 букв (`"A"`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-09**: Валидация `CountryIsoCode` — длина больше 2 букв (`"RUS"`, `"USA"`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-10**: Валидация `CountryIsoCode` — наличие цифр (`"R1"`, `"12"`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-11**: Валидация `CountryIsoCode` — наличие спецсимволов (`"R!"`, `"$U"`, `"R "`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-12**: Валидация `CountryIsoCode` — нелатинские символы (кириллица `"РФ"`, греческий, умлауты).
  - *Ожидаемый результат*: HTTP 400 Bad Request (разрешена строго латиница).
- [ ] **TC-POST-13**: Валидация `Locale` — пустая строка `""`.
  - *Ожидаемый результат*: HTTP 400 Bad Request с описанием ошибки поля `Locale`.
- [ ] **TC-POST-14**: Валидация `Locale` — строка из пробелов `"   "`.
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-15**: Валидация `Locale` — значение `null`.
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-16**: Валидация `Locale` — неверный регистр страны (строчные вместо прописных, например `"ru-ru"`).
  - *Ожидаемый результат*: HTTP 400 Bad Request (строго формат `xx-XX`).
- [ ] **TC-POST-17**: Валидация `Locale` — неверный регистр языка (прописные вместо строчных, например `"RU-RU"`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-18**: Валидация `Locale` — инвертированный регистр (`"RU-ru"`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-19**: Валидация `Locale` — отсутствие дефиса (`"ruRU"`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-20**: Валидация `Locale` — символ подчеркивания вместо дефиса (`"ru_RU"`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-21**: Валидация `Locale` — трехбуквенные коды (`"rus-RU"`, `"ru-RUS"`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-22**: Валидация `Locale` — наличие цифр или спецсимволов (`"r1-RU"`, `"ru-R!"`, `"12-34"`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-23**: Валидация `Locale` — нелатинские символы (кириллица `"ру-РУ"`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-24**: Передача пустого тела запроса или невалидного JSON (синтаксическая ошибка JSON).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-POST-25**: Попытка передать `userId`, `dateCreated`, `dateModified` в теле запроса `UserDto`.
  - *Ожидаемый результат*: Поля игнорируются сервером, `userId` и `dateCreated` генерируются заново, `dateModified` устанавливается в `null`.

## 2. GET /api/users/{userId} — Получение пользователя по ID

### Позитивные проверки
- [ ] **TC-GET-01**: Успешное получение ранее созданного пользователя по существующему `userId`.
  - *Ожидаемый результат*: HTTP 200 OK; тело ответа полностью совпадает с сохраненными данными пользователя.
- [ ] **TC-GET-02**: Корректность формата времени UTC (`dateCreated` и `dateModified` при наличии).
  - *Ожидаемый результат*: HTTP 200 OK; даты в формате ISO 8601 (UTC).

### Негативные проверки
- [ ] **TC-GET-03**: Запрос с несуществующим валидным GUID (случайный `Guid.NewGuid()`).
  - *Ожидаемый результат*: HTTP 404 Not Found с понятным сообщением (пользователь не найден).
- [ ] **TC-GET-04**: Запрос с пустым GUID (`00000000-0000-0000-0000-000000000000` / `Guid.Empty`).
  - *Ожидаемый результат*: HTTP 400 Bad Request (пустой GUID запрещен требованиями).
- [ ] **TC-GET-05**: Запрос с невалидным форматом GUID (строка `"invalid-guid"`, число `"12345"`, спецсимволы).
  - *Ожидаемый результат*: HTTP 400 Bad Request.

## 3. PUT /api/users/{userId} — Обновление пользователя

### Позитивные проверки
- [ ] **TC-PUT-01**: Успешное обновление существующего пользователя валидными данными (`CountryIsoCode` и `Locale`).
  - *Ожидаемый результат*: HTTP 200 OK; возвращены обновленные данные; `dateModified` заполнен (не null, значение >= `dateCreated`); `userId` и `dateCreated` не изменились.
- [ ] **TC-PUT-02**: Приведение `CountryIsoCode` к верхнему регистру при обновлении (`"de"` -> `"DE"`).
  - *Ожидаемый результат*: HTTP 200 OK; в ответе `countryIsoCode: "DE"`.
- [ ] **TC-PUT-03**: Повторное обновление пользователя с проверкой изменения `dateModified`.
  - *Ожидаемый результат*: HTTP 200 OK; `dateModified` обновляется на более позднее время.

### Негативные проверки
- [ ] **TC-PUT-04**: Обновление несуществующего пользователя по случайному валидному GUID.
  - *Ожидаемый результат*: HTTP 404 Not Found.
- [ ] **TC-PUT-05**: Обновление с пустым GUID (`Guid.Empty`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-PUT-06**: Обновление с невалидным форматом GUID в URL (`"not-a-guid"`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-PUT-07**: Обновление с невалидным `CountryIsoCode` (пустой, цифры, символы, неверная длина).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-PUT-08**: Обновление с невалидной `Locale` (пустая, неверный регистр, без дефиса).
  - *Ожидаемый результат*: HTTP 400 Bad Request.
- [ ] **TC-PUT-09**: Обновление с пустым или синтаксически неверным телом запроса.
  - *Ожидаемый результат*: HTTP 400 Bad Request.

## 4. GET /api/users — Получение списка всех пользователей и Пагинация (Доп. задание 1)

### Позитивные проверки
- [ ] **TC-LIST-01**: Получение списка пользователей при пустой базе данных.
  - *Ожидаемый результат*: HTTP 200 OK; возвращается пустой список/коллекция (`items: []` или `[]`).
- [ ] **TC-LIST-02**: Получение списка всех пользователей без параметров пагинации.
  - *Ожидаемый результат*: HTTP 200 OK; возвращаются все созданные пользователи.
- [ ] **TC-PAG-01**: Пагинация — первая страница (`page=1&pageSize=2`) при наличии 5 пользователей.
  - *Ожидаемый результат*: HTTP 200 OK; возвращены ровно 2 пользователя первой страницы, метаданные пагинации корректны (`page: 1`, `pageSize: 2`, `totalCount: 5`).
- [ ] **TC-PAG-02**: Пагинация — вторая страница (`page=2&pageSize=2`).
  - *Ожидаемый результат*: HTTP 200 OK; возвращены 2 пользователя второй страницы, не пересекающиеся с первой страницей.
- [ ] **TC-PAG-03**: Пагинация — последняя неполная страница (`page=3&pageSize=2`).
  - *Ожидаемый результат*: HTTP 200 OK; возвращен оставшийся 1 пользователь.
- [ ] **TC-PAG-04**: Пагинация — страница за пределами диапазона (`page=10&pageSize=2`).
  - *Ожидаемый результат*: HTTP 200 OK; список элементов пуст, `totalCount: 5`.
- [ ] **TC-PAG-05**: Пагинация — граничное значение `page=1`, `pageSize=1`.
  - *Ожидаемый результат*: HTTP 200 OK; возвращен 1 элемент.

### Негативные проверки пагинации
- [ ] **TC-PAG-06**: Передача `page = 0` или отрицательного `page = -1`.
  - *Ожидаемый результат*: HTTP 400 Bad Request с понятной ошибкой (`page` должен быть >= 1).
- [ ] **TC-PAG-07**: Передача `pageSize = 0` или отрицательного `pageSize = -5`.
  - *Ожидаемый результат*: HTTP 400 Bad Request (`pageSize` должен быть >= 1).
- [ ] **TC-PAG-08**: Передача `pageSize` превышающего допустимый максимум (защита от DoS, `pageSize > 100`).
  - *Ожидаемый результат*: HTTP 400 Bad Request с сообщением о превышении максимального размера страницы.
- [ ] **TC-PAG-09**: Передача нечисловых параметров пагинации (`page=abc`, `pageSize=xyz`).
  - *Ожидаемый результат*: HTTP 400 Bad Request.

## 7. Сквозной E2E-сценарий (End-to-End Workflow)

- [ ] **TC-E2E-01**: Полный жизненный цикл пользователя:
  1. `POST /api/users` с `{"countryIsoCode": "us", "locale": "en-US"}` -> 201 Created, сохраняем `userId`, проверяем `dateCreated`, `dateModified == null`, `countryIsoCode == "US"`.
  2. `GET /api/users/{userId}` -> 200 OK, проверяем соответствие всех полей объекту из шага 1.
  3. `PUT /api/users/{userId}` с `{"countryIsoCode": "gb", "locale": "en-GB"}` -> 200 OK, проверяем обновление полей и непустой `dateModified >= dateCreated`.
  4. `GET /api/users/{userId}` -> 200 OK, повторно проверяем, что данные применились и сохранены персистентно в in-memory репозитории.
  5. `GET /api/users` -> 200 OK, проверяем наличие пользователя в общем списке.

## 8. Потокобезопасность и конкурентность (Concurrency & Thread-Safety)

- [ ] **TC-TH-01**: Одновременное создание множества пользователей из параллельных потоков (`Parallel.For` / `Task.WhenAll`).
  - *Ожидаемый результат*: Все пользователи успешно созданы, количество записей в репозитории строго равно количеству запросов, гонок данных нет.
- [ ] **TC-TH-02**: Параллельные операции чтения и обновления одних и тех же пользователей.
  - *Ожидаемый результат*: Отсутствие `InvalidOperationException`, `NullReferenceException` или деградации целостности данных.

## 9. Изоляция автотестов

- [ ] **TC-ISO-01**: Независимость тестов: Тест А создает пользователей, завершается; Тест Б стартует с гарантированно пустым состоянием репозитория.
  - *Ожидаемый результат*: Тест Б видит строго чистое хранилище, тесты взаимно не влияют на результаты друг друга при любом порядке выполнения.
