## Выполненные этапы и требования

### Этап 1: Тест-дизайн
Создан файл `test-cases.md` в корне проекта с исчерпывающим чек-листом позитивных, негативных, граничных и нефункциональных проверок.

### Этап 2: Реализация REST API сервиса
- **Модель `User`**: `UserId` (Guid), `CountryIsoCode` (string), `DateCreated` (DateTime UTC), `DateModified` (DateTime? UTC, изначально null), `Locale` (string).
- **DTO `UserDto`**: содержит только `CountryIsoCode` и `Locale`.
- **Интерфейс `IUserRepository`**: методы `Add`, `Update`, `GetById`, `GetAll` (и `Clear` для изоляции тестов).
- **Потокобезопасность (`InMemoryUserRepository`)**:
  - Хранилище на базе `ConcurrentDictionary<Guid, User>`.
  - Защитные копии (**Defensive Copies**) при чтении и записи, исключающие гонки мутаций ссылочных типов.
  - Атомарное обновление с использованием паттерна CAS (Compare-And-Swap через `TryUpdate`).
- **Эндпоинты `UsersController`**:
  - `POST /api/users`: генерация ID и `DateCreated`, возврат **201 Created** с телом и заголовком `Location`.
  - `PUT /api/users/{userId}`: обновление `CountryIsoCode`, `Locale` и `DateModified`, возврат **200 OK** или **404 Not Found**.
  - `GET /api/users/{userId}`: возврат **200 OK** или **404 Not Found**.
  - `GET /api/users`: возврат **200 OK** со списком объектов (и поддержкой пагинации).

### Этап 3: Валидация входных данных
- **`UserId` в URL**: проверка валидности формата GUID, запрет пустого `Guid.Empty` (`00000000-0000-0000-0000-000000000000`) -> возврат **400 Bad Request**.
- **`CountryIsoCode`**: строго 2 буквы латиницы (`^[a-zA-Z]{2}$`), регистронезависимо, при сохранении приводится к **UPPERCASE** (`ToUpperInvariant()`).
- **`Locale`**: строго формат `xx-XX` (`^[a-z]{2}-[A-Z]{2}$`, две строчные буквы латиницы, дефис, две прописные буквы латиницы, например `ru-RU`, `en-US`).
- Возврат информативных сообщений об ошибках в формате `ErrorResponseDto` (RFC 7807).

### Этап 4: Написание автотестов (xUnit + WebApplicationFactory)
- **Изоляция тестов (Test Isolation)**: `TestBase` в конструкторе вызывает `Factory.ResetRepository()`, обеспечивая 100% чистый сброс хранилища перед каждым тестом (Тест А изолирован от Теста Б).
- **Data-Driven тестирование**: параметризованные тесты `[Theory]` и `[InlineData]` проверяют свыше 10 невалидных комбинаций для каждого поля (пустые строки, пробелы, спецсимволы, цифры, неверная длина, инвертированный регистр, кириллица).
- **Проверка схемы и типов**: десериализация JSON-ответов и строгая проверка всех полей (`UserId != Guid.Empty`, диапазоны дат, нормализация регистра).
- **Сквозной E2E сценарий**: создание через POST -> получение через GET -> модификация через PUT -> проверка через GET.

## 🌟 Дополнительные задания (со всеми допами)

### 1. Пагинация (`GET /api/users?page={page}&pageSize={pageSize}`)
- Параметры: `page` (по умолчанию 1) и `pageSize` (по умолчанию 10, максимум 100 для защиты от DoS).
- Валидация параметров пагинации (возврат 400 при `page < 1`, `pageSize < 1`, `pageSize > 100`).
- Добавление полезных заголовков ответа: `X-Total-Count`, `X-Page`, `X-Page-Size`, `X-Total-Pages`.
- Автотесты в `PaginationTests.cs`: проверка разбиения на страницы, остаточных страниц и выхода за диапазон.

### 2. Глобальная обработка ошибок (Custom Middleware)
- Реализован `ExceptionHandlingMiddleware`, перехватывающий любые непредвиденные исключения в конвейере ASP.NET Core.
- Возвращает клиенту стандартизированный чистый JSON со статусом **500 Internal Server Error**.
- **Безопасность (Security)**: предотвращает утечку внутренней информации (Information Disclosure) — исключает стектрейсы, пути файлов и имена внутренних классов из ответа клиенту.
- Автотесты в `ErrorHandlingTests.cs`: провокация ошибки через контроллер и через отказ репозитория с проверкой чистоты тела ответа.

### 3. Логирование в тестах через `ITestOutputHelper`
- В API настроено структурированное логирование через `ILogger` (в контроллерах, middleware, репозитории).
- Реализованы `XUnitLogger` и `XUnitLoggerProvider`, перенаправляющие внутренние логи приложения напрямую в `ITestOutputHelper`.
- Логи эндпоинтов выводятся в консоль теста и отчеты CI (например, при запуске с `--logger "console;verbosity=detailed"`).
- Автотест в `LoggingTests.cs` программно подтверждает поступление логов API в xUnit вывод.

```bash
dotnet test
```

```bash
dotnet test --logger "console;verbosity=detailed"
```

```bash
dotnet run --project UserManagement.API
```
